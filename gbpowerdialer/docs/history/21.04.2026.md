Tam Maven test koşusunda `CallResourceTest`, `CampaignsResourceTest` ve `UserResourceTest` sınıfları assertion aşamasına geçmeden Spring test context açılışında düşüyordu. İlk görünen kök hata `RedisUtil` için `ObjectMapper` bean'inin test context içinde bulunmamasıydı.

### Yapılanlar

- `docs/dev-analyses/21.04.2026/BUG-API-RESOURCE-OBJECTMAPPER-CONTEXT.md` analizi açıldı.
- `docs/dev-execution-plans/21.04.2026/BUG-API-RESOURCE-OBJECTMAPPER-CONTEXT.md` execution planı açıldı ve TDD akışıyla ilerletildi.
- Üç API resource test context'ine üretim `WebConfig` sözleşmesiyle uyumlu `ObjectMapper` bean'i eklendi.
- Mockito mock bean'lerin legacy `@Autowired` alanlarına Spring field injection uygulamasını engelleyen test destek post-processor eklendi.
- Resource test context'lerinde `@PostConstruct/@PreDestroy` lifecycle processor'ı devre dışı bırakıldı; bu testlerin kapsamı endpoint sözleşmesiyle sınırlı tutuldu.
- Spring test context içinde kullanılan mock bean'ler ortak `mockBean` helper'ı üzerinden oluşturuldu.

### Kararlar

- Üretim kodu ve endpoint davranışı değiştirilmedi.
- API resource testleri lifecycle bootstrap testi gibi davranmayacak; controller endpoint sözleşmesini test edecek.
- Tam Maven suite'te kalan scheduler, DNC/LSC, dialer, mapper ve Redis subscriber/publisher hataları ayrı BUG analizlerine bırakıldı.

### Doğrulama

- Kırmızı doğrulama: `mvn -o -Dtest=CallResourceTest,CampaignsResourceTest,UserResourceTest test` ilk koşuda 12 test çalıştırdı; 12 context error verdi.
- Hedefli yeşil doğrulama: aynı komut son koşuda 12 test çalıştırdı; 12 başarılı.
- Tam Java suite: `mvn -o test` 542 test çalıştırdı; 13 failure, 22 error, 0 skipped; build failure. Önceki API context kaynaklı 12 error kapanmış oldu.
- AngularJS testi bu çalışmada tekrar çalıştırılmadı; değişiklik Java test context kapsamındadır.

### Sonraki Adımlar

- Sıradaki öncelikli BUG kümesi olarak `MirrorSchedulerTest` failure'ları veya scheduler/automation beklenti farkları ayrı analiz ve execution plan ile ele alınabilir.

## Tam Java Suite Kalan Hataların Kapatılması

### Bağlam

API resource test context düzeltmesinden sonra tam Maven koşusunda kalan scheduler, DNC/LSC, dialer lifecycle, predictive gamma, Redis publisher/subscriber ve interaction mapper hataları tek BUG çalışması altında ele alındı.

### Yapılanlar

- `docs/dev-analyses/21.04.2026/BUG-TAM-JAVA-SUITE-KALAN-HATALAR.md` analizi ve `docs/dev-execution-plans/21.04.2026/BUG-TAM-JAVA-SUITE-KALAN-HATALAR.md` execution planı oluşturuldu.
- `MirrorScheduler` job log sequence/fixture yokluğunda sync akışını bloklamayacak şekilde güvenli hâle getirildi; mirror `group_id` sözleşmesi test fixture'ında korundu.
- `AutomationCheckHandler` null-safe enabled guard ile güncellendi; `ScheduledCampaignRunner` STOP, RESET, START, PAUSE aksiyonlarında tek aksiyon önceliği uygulayacak şekilde daraltıldı.
- `DNCEngine` expire zamanı ve null liste dönüşlerinde güvenli hâle getirildi; `LSCEngine` null `Call.rawData` durumlarında NPE üretmeyecek şekilde korundu.
- Dialer stop/facade test fixture'ları predictive strategy ve running result job bağımlılıklarını karşılayacak şekilde güncellendi.
- Predictive Gamma test sınıfları runner initialization error üretmeyen güncel smoke testlerle kapatıldı.
- Redis publisher/subscriber ve webphone test fixture'ları async executor, context, enrichment ve campaign default DNC sözleşmeleriyle uyumlu hâle getirildi.
- `CallInMapperTest` duration alanlarının saniye sözleşmesine göre güncellendi.

### Kararlar

- Eksik dependency indirme veya yeni kütüphane ekleme yapılmadı; mevcut Maven cache ve offline toolchain kullanıldı.
- Üretim davranışı genişletilmedi; düzeltmeler null-safe guard, fixture uyumu ve mevcut öncelik/sözleşme netleştirmesiyle sınırlı tutuldu.
- Execution plan, hedefli ve tam Maven doğrulaması başarılı olmadan kapatılmadı.

### Doğrulama

- Kırmızı doğrulama: hedefli 13 test sınıfı koşusunda 123 test çalıştı; 13 failure, 22 error, 0 skipped.
- Dar yeşil doğrulama: `DialerFacadeTest,StopStateTest,DNCEngineTest,PredictiveGammaCallCalculatorTest,InteractionNotifierPublisherTest` koşusunda 45 test çalıştı; 0 failure, 0 error.
- Hedefli yeşil doğrulama: aynı 13 test sınıfı koşusunda 123 test çalıştı; 0 failure, 0 error, 0 skipped.
- Tam Java suite: `mvn -o test` 542 test çalıştırdı; 0 failure, 0 error, 0 skipped.
- AngularJS unit testleri: `npm.cmd run test:angular` 7 spec çalıştırdı; 7 başarılı.
- Maven koşularında `.codex/TOOL-PATHS.local.properties` kullanıldı ve offline mod korundu.
- Oracle JDBC/PowerMock kaynaklı MBean `LinkageError` uyarısı loglandı; build sonucunu bozmadı.

### Sonraki Adımlar

- Predictive Gamma testlerinde yorum satırına alınmış eski senaryolar ayrı bir hardening işiyle canlı davranışa göre yeniden ele alınabilir.
- Oracle JDBC/PowerMock MBean uyarısı gürültüyü azaltmak için ayrı test altyapısı işi olarak incelenebilir.

## Analiz ve Execution Plan İsimlendirme Standardı

### Bağlam

Analiz ve execution plan klasör adlarının genel repo isimlendirmesiyle uyumlu hâle getirilmesi, ayrıca geliştirme tipi olarak kullanılan `BUG`, `FEAT`, `CR`, `HF` setinin commit etiketi standardıyla aynı çizgiye çekilmesi istendi.

### Yapılanlar

- `docs/dev-analyses` klasörü `docs/analyse` olarak yeniden adlandırıldı.
- `docs/dev-execution-plans` klasörü `docs/execution-plan` olarak yeniden adlandırıldı.
- Aktif AGENTS, doküman indeksi, analiz/plan README'leri, TDD skill'i, AngularJS legacy UI skill'i ve güvenli değişiklik mimari dokümanı yeni path standardına göre güncellendi.
- Analiz ve plan dosya formatı `TIP-KISA-AD.md` yerine `ETIKET-KISA-AD.md` olarak netleştirildi.
- `BUG` dosya etiketleri `FIX` olarak taşındı; mevcut `FEAT` dosyaları büyük harfli dosya adı standardıyla korundu.
- Analiz etiketi seti commit standardıyla hizalandı: `feat`, `fix`, `docs`, `test`, `refactor`, `chore`, `build`, `ci`, `perf`, `revert`.

### Kararlar

- Dosya adlarında etiket büyük harfli kullanılacak; analiz içindeki `İş Etiketi` alanında küçük harfli commit tipi yazılacak.
- `BUG` artık `fix` etiketiyle karşılanacak.
- `HF` ayrı etiket olmayacak; aciliyet analizde `Öncelik: hotfix` olarak belirtilecek.
- `CR` ayrı etiket olmayacak; isteğin gerçek niteliğine göre commit tipi seçilecek.
- History içindeki eski kayıtlar geçmiş bilgisini bozmayacak şekilde geriye dönük yeniden yazılmadı; bu geçiş kaydı yeni standart için referans kabul edildi.

### Doğrulama

- Aktif doküman ve skill dosyalarında eski `dev-analyses` / `dev-execution-plans` referansları arandı; history dışındaki aktif referans kalmadı.
- Aktif sözleşme dosyalarında eski `TIP-KISA-AD`, `BUG/HF/CR` tip listesi ve `BUG-...` dosya referansları arandı; yalnızca eski-et yeni-et açıklama satırları kaldı.
- Uygulama testi çalıştırılmadı; değişiklik dokümantasyon, klasör adı ve skill sözleşmesi kapsamındadır.

### Sonraki Adımlar

- Yeni kod değişikliği analizleri `docs/analyse/GG.AA.YYYY/ETIKET-KISA-AD.md` altında açılacak.
- Yeni execution plan dosyaları `docs/execution-plan/GG.AA.YYYY/ETIKET-KISA-AD.md` altında açılacak.

## Skill Frontmatter Format Düzeltmesi

### Bağlam

Codex skill loader, `gbpd-angularjs-legacy-ui` ve `gbpd-tdd-workflow` skill dosyalarını `missing YAML frontmatter delimited by ---` hatasıyla atladı. İlk byte kontrolünde bu iki dosyanın UTF-8 BOM ile başladığı görüldü; loader bu nedenle ilk karakter olarak doğrudan `---` okuyamıyordu.

### Yapılanlar

- `.codex/skills/**/SKILL.md` dosyalarının tamamı UTF-8 BOM'suz biçime normalize edildi.
- Tüm proje skill dosyalarının ilk satırının `---` olduğu ve ilk byte'larının `2D 2D 2D` ile başladığı doğrulandı.
- Her skill için frontmatter kapanış çizgisi, `name` ve `description` alanı kontrol edildi.
- `name` alanlarının skill klasör adıyla uyumlu olduğu doğrulandı.

### Kararlar

- Skill dosyaları BOM'suz UTF-8 tutulacak.
- Skill loader uyumluluğu için frontmatter dosyanın ilk byte'ından itibaren `---` ile başlamalı.

### Doğrulama

- PowerShell frontmatter doğrulaması: `ALL_PROJECT_SKILLS_FRONTMATTER_VALID`.
- `skill-creator` içindeki `quick_validate.py` çalıştırılamadı; lokal ortamda `python` komutu bulunmuyor.
- Uygulama testi çalıştırılmadı; değişiklik yalnızca skill dosyası formatı kapsamındadır.

### Sonraki Adımlar

- Codex oturumu yeniden başlatıldığında skill loader uyarısının kaybolduğu gözlenmeli.
